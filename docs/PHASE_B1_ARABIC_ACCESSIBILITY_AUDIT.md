# Phase B1 — Arabic localization and accessibility evidence (2026-10-17)

## Implementation
- Dynamic Arabic output additions committed to `app/index.b1.tsx`; includes educational consultation fallback, common Arabic symptom/emergency keywords, lab classifications and safe explanation fallback, nutrition notes and meals, BMI classification labels, and workout labels/cautions.
- New synthetic browser coverage: `tests/test_b1_dynamic_arabic.py` and `tests/test_b1_accessibility_proxies.py`.
- These changes are review-only. Production Railway Function is unchanged.

## Translation limitations / clinical review
- Dictionary-based substring substitution is a transitional implementation, not a fully key-based localization architecture.
- Arabic symptom recognition is a limited keyword list, not comprehensive Arabic clinical NLP; unknown symptoms should receive safe general guidance.
- Clinical Arabic language and safety messages require review by a qualified Arabic-speaking clinician or healthcare translator before production.
- Dynamic output generated by all 11 sections must be sampled by human reviewers, especially symptom, lab, nutrition, fitness, BMI and vitals results.
- Check locale switching after generating content; some already-rendered conversation bubbles may not be relocalized without rerendering.
- Avoid claiming complete bilingual medical accuracy.

## Automated accessibility evidence
Playwright checks test basic keyboard focus, language/RTL metadata, 320px layout proxy, and chart textual output. Existing axe-core checks test automated WCAG tags. These tests are **not** manual accessibility validation.
